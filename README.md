# Before you start

Please read the following documents **completely** before writing any code:

1. **`README.md` (this document)** — repository setup and submission instructions.
2. **`01_candidate_take_home.md`** — the exercise brief, task breakdown, invariants, and evaluation criteria.
3. **`starter/README.md`** — how to run the starter scaffold and what is already implemented.

There are several important constraints and design expectations explained throughout these documents. Reading them carefully will usually save you time.

---

# Repository setup

1. Clone this repository locally.

2. Create a branch using your **full name** in lowercase with dash separators.

   Example:

   ```text
   june-jung
   ```

3. Complete all of your work on that branch.

We use separate branches to keep candidate submissions isolated.

# Working guidelines

## Timebox

Please spend **approximately 2 hours** on this exercise.

Track your time honestly and stop at the 2-hour mark, even if you are not finished.

We care much more about:

- how you approached the problem,
- your engineering decisions,
- your prioritization,

than whether every endpoint is complete.

---

## Commit history

Please commit regularly.

Small, focused commits with meaningful commit messages are strongly preferred.

Ideally your commits should align with the task breakdown in the exercise (T1, T2, etc.).

We review commit history because it helps us understand your thought process.

---

## AI assistance

Please avoid using AI coding assistants (ChatGPT, Claude, Copilot, Cursor, etc.) during this exercise.

We want to evaluate your own engineering thinking.

If you did use AI for any specific part, simply disclose it at the bottom of your README.

There is **no penalty for honest disclosure**. The only concern is being unable to explain code that you claim to have written.

---

# Submission

When you are finished (or when your 2 hours are up):

```bash
git push origin your-full-name
```

Then reply to the interview invitation email to let us know your submission is ready.

---

# What happens next

After reviewing your submission, we'll schedule a **1-hour pairing session**.

During the session we'll extend your solution using a realistic operational scenario.

You'll continue working in **your own codebase**—you won't be asked to whiteboard solutions from scratch.

---

# Setup issues

If you encounter any setup problems before starting your 2-hour window (repository access, scaffold issues, environment problems, etc.), please contact us.

We would much rather help resolve setup issues upfront than have you spend your exercise time troubleshooting your environment.

---

Good luck, and thank you again for your time.
